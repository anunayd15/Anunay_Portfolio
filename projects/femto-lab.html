OVERVIEW

Automating the transfer of locally generated lab data to cloud storage

This project began in the Femto Lab at The University of Texas at Austin as an effort to automate and simplify the process of transferring locally generated laboratory data to cloud storage.

Rather than manually identifying and uploading files, I explored Python-based workflows that could select files based on user-defined patterns and automate their transfer from a local computer to UT Box.

I developed two approaches to the problem: a direct synchronization method and a client/server method using a Flask API.

DIRECT APPROACH

Compare first then upload only what's missing

The direct synchronization script was designed to reduce unnecessary file transfers by checking the contents of remote storage before uploading.

ARCHITECTURE

Why separate the system into a client and server?

The API approach separates the request to upload files from the implementation responsible for interacting with remote storage.

Client Responsibility

The client only needs to identify the desired files and send them to a defined API endpoint. Furthermore, the client has the ability to go through their file explorer and select files manually, rather than relying on a command-line.

Server Responsibility

The Flask application handles receiving the files, saving them locally, executing the transfer command, and returning a success or error response.

Why This Matters

Separating these responsibilities creates a cleaner interface between file-generating applications and the remote-storage workflow. A client can request an upload without needing to implement the underlying Box transfer process itself while having the ability to select files through a GUI rather than a command-line.

OUTCOME

Turning a repetitive file-management task into an automated workflow

The project explored how Python automation and a simple API architecture could reduce the manual effort required to move locally generated files into shared remote storage.

The direct implementation focused on identifying and transferring missing files, while the API implementation separated file selection from the underlying upload process.

For a laboratory workflow, this architecture could be used to automate the transfer of generated experimental images from a local acquisition computer into a shared cloud storage.
